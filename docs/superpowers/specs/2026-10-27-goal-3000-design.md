# 3000ラリークリア・殿堂入り

## 確定した仕様

3000ラリー目の有効な返球でゲームクリアとする。到達までの最大30球、増球、速度、衝突、入力、固定時間刻み、停止条件は維持する。到達後は得点・物理計算を進めない。終了を落球による失敗と明示的に区別する。結果は静かな画面で示し、継続する3D描画を止める。

殿堂入り番号は登録名を既存の方法で正規化した単位の初回登録順。同名の再クリアは同じ番号を返す。人の人数とは表現せず「殿堂登録 第○号」とする。新ルールの開始RPCで始めたプレイのみ対象とし、旧記録は変更・移行しない。

## 実装方針（実装者の選択）

既存のDraft PR #27へ最新mainのランキング保護・最終落球数を統合する。新しい専用開始/終了RPCがルール版をセッションに記録し、既存の終了・スコア送信の検証を再利用する。殿堂登録はスコア送信成功後の専用RPCで行う。登録名単位の一意制約とトランザクション内の採番で、再送や同時リクエストによる二重登録を防ぐ。ランキング対象外の名前は殿堂一覧にも掲載しない。欠番を再利用したり後から番号を詰めたりしない。

ブラウザー内の番号だけで正式登録を装う案は採用しない。賞状をサーバーへ画像保存する案も採用しない。PNGはクリア後、必要時にCanvas 2Dで一度生成し、名前・登録番号・初回登録日を含める。プレビューから保存でき、対応ブラウザーでは画像共有もできる。画像生成はプレイ中のフレーム処理へ追加しない。

通信待ちでは「殿堂登録中」、失敗時は再送状態を示す。正式な番号はサーバー応答が確定してから表示する。別プレイやホームへ移った後の遅い応答は現在の結果を上書きしない。名前なしでもクリアと番号なしの達成賞状を利用できる。登録名が必要な旨は開始前に示す。

ホームの目標、HUD、クリア/未達の結果メッセージ、X共有、ランキングマニフェストを更新する。既存の結果44段階コメントは未達結果用に残し、クリア用の文言を別に用意する。3000の到達音を保ち、クリア画面には新たな点滅を追加しない。

## 検証と公開境界

同一tickで複数球が返る際の3000止め、一度だけのクリアイベント、到達前の30球同時返球、失敗・中断との区別を検証する。ローカルPostgres互換環境で新旧セッション、同名再送、別名順序、不正入力、対象外名、権限を検証する。本番ランキングへテストを送らず、本番DBへマイグレーションを適用しない。

Chromium/WebKitで結果、賞状PNG、長い名前、通信失敗と再送、リトライ、入力、停止後の描画回数を検証する。元のLinux性能目標と点滅解析閾値を維持する。3000で終了しても、未達段階の性能・点滅問題がすべて解消したとは主張しない。iPhone実機は利用できず、Safari実機性能は未確認として残す。

マイグレーション・ソース・検証結果をDraft PRへ提出する。マージ、本番DB反映、Pages公開は行わない。
