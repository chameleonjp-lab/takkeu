# 4000ラリー演出拡張 — 設計・保護方針

## 目的と確定条件
0〜4000の到達感をゲーム世界に追加し、4001以降も継続する。得点、最大30球、増球、100球落球終了、加速、450スマッシュ、555バウンド、直接入力、ランキング・保存・共有は維持する。ユーザーの17章の依頼を仕様の正とし、省略や設計承認待ちは行わない。

## 調査と設計判断
PR #26は2026-10-25にマージ済み（aff31169fd6feaad7bad35f22fe3de26429296cf）。最新mainから専用ブランチを作る。結果コメント・SVG電撃・順位機能を再実装しない。resultComment(score)を通常通知に再利用するが結果ファイルは変更しない。

候補は既存milestoneの拡張と、独立した演出管理。前者は増球報酬と演出を混同する危険があるため、後者を採用する（実装判断）。GameEventの確定player-hit/rallyScoreとball-lost/positionを入力とし、ゲーム内simTimeによる上限付きの一時状態と宣言的な常設段階を管理する。Three.jsは描画にのみ使用し、ゲーム用乱数を呼ばない。演出は時刻・種・固定インデックスから再現可能にする。

## 責務とインターフェース
- game: 得点・落球事実。落球座標は判定時にコピーする。
- game/presentation: 条件、時間、優先度、置換、初期best、発生済みスコア、短い落球窓。過去の全履歴は保存しない。
- render: 固定数の線・点・光輪を再利用。カメラと入力投影は変更しない。2000星空は不透明コートに隠れないカメラ可視域へ配置する。
- ui: 入力を奪わない通知領域。通常1.8秒、主要4節目2.5秒、best2秒。主要節目を優先する。毎ラリーの読み上げは追加しない。
- audio: Web Audio生成音を追加。1000/3000/4000のみ通常ファンファーレを置換。警告時は祝福音をduckし、voice上限でも警告を落とさない。
- app: 保存bestをプレイ開始時にコピー。finishPresentationの最大5秒に統合し、スコア確定・通信開始は既存時点を維持する。

## 検証と納品の区別
実装、unit/browser自動検証、描画画像の内容確認、動作証拠、音声波形、人間試聴、実機性能を別々に記録する。外部通信はテストで遮断し既存モックを使う。本番へ高スコアを送らない。単なるスコア設定と0→4000物理計算を別々に検証する。性能は変更前後の同環境複数回、標準/低、30球/60秒、1500/2000/3000/4000で測る。Linux目標未達と実機未確認を隠さない。WCAGの映像閾値検証は自動的な証明と人間の確認を混同しない。

## 納品
設計、全条件対応表、3段階計画、変更ファイル、正式ログ、画像/連続画像、性能・音声・光安全性・敵対的検証・独立レビューをdocs/へ保存する。段階別コミット、main向けDraft PR。マージ・公開・DB変更はしない。
