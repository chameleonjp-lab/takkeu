# 残球加速と待機球の非表示

依頼の仕様を実装基準とする。基点mainは `8f2a025`（マージ済みPR #15）。PR #15のランキング・共有・リトライ変更と、既存のdifficulty / flightSpeed / scheduler / simulation / presentationを確認した。

- 100ラリーちょうどから、相手の打球時の未失球数（queued / waiting-return / outgoing / incoming）で4球以上1、3球1.25、2球1.5、1球2倍。飛行中は固定、プレイヤーの返球は対象外。
- `remainingBallMultiplier`を基本加速・スマッシュと分離してReturnPlanへ記録する。既存の最低時間を含む基本飛行時間をこの値で割る。ラリーの全球加速は継続し、同じ追加倍率で新旧時間を比較して位置を保存する。
- 待機中の予約は暫定値。実際の出発時に現在のscore・残球で再予約し、既存の到着間隔を守る。衝突する場合は出発を遅らせ、待機後にもう一度判定する。既存の予告音・0.4秒以上の予告・軌道のbounceXを保存する。
- queued / waiting-return / lostは相手側でも自側でも常時非表示。移動中だけ既存の発光・420〜479不可視規則と相手コート領域の解放（右190、左240、連続模様490）を適用する。縁70だけでは球を表示しない。単一の判定で本体・影・発光・輪郭を制御する。
- ランキング、共有、画面構成、増球・虹色・花火・スマッシュの進行は変更しない。Draft PRまで作成し、merge・公開は実行しない。

## 実装判断
生存数を毎フレーム速度へ直接反映すると飛行中の倍率固定を破る。基本倍率へ組み込むと最低時間で頭打ちになり、更新時に二重適用しやすいため独立値を採用する。予約済み待機球をそのまま加速すると到着間隔が壊れるため、打球確定時にもschedulerを通す。

## 検証
99/100/101 × 1/2/3/4/8球の実移動時間、450/540/555スマッシュ、打球前後の失球と増球、重複予約、全球加速時の位置・接触、停止/再開/リトライを自動検査する。待機前後と虹色未解放/片側/全面解放を、描画インスタンスとiPhone縦画面のWebKit画像で確認する。既存unit・browser・配布検査を実行し失敗履歴も保存する。実機iPhoneの操作・性能は自動ブラウザ検査と区別する。
