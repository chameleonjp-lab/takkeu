# 残球加速と待機球の非表示

2026-10-24の共有・残球速度・多層効果音の依頼を現行の実装基準とする。基点mainは `27ebee8fb5fa0d29f7f82e15244dd1fbd1a88de1`。最初の残球速度実装（旧基点 `8f2a025`）の2/1.5/1.25倍は下記へ置換する。旧実装の検証記録は当時の履歴として残す。

- 0–99ラリーは常に1倍。100ラリーちょうどから、相手の実際の打球時の未失球数（queued / waiting-return / outgoing / incoming）で1球1.4、2球1.3、3球1.2、4球1.1、5球以上1倍。不正score・残球数（非有限/負数/非整数、残球0）は安全な1倍とし、最後の失球後は新しい打球を発生させない。飛行中の残球倍率は固定、プレイヤーの返球は対象外。
- `remainingBallMultiplier`を基本加速・スマッシュと分離してReturnPlanへ記録する。既存の最低時間を含む基本飛行時間をこの値で割る。ラリーの全球加速は継続し、同じ追加倍率で新旧時間を比較して位置を保存する。
- 待機中の予約は暫定値。実際の出発時に現在のscore・残球で再予約し、既存の到着間隔を守る。衝突する場合は出発を遅らせ、待機後にもう一度判定する。既存の予告音・0.4秒以上の予告・軌道のbounceXを保存する。同時刻の既存action処理はバウンドを先に、それ以外は球ID昇順。打球前に処理した失球/加点/増球を残球倍率へ含め、打球後の変更は飛行中の球へ遡及しない。
- queued / waiting-return / lostは相手側でも自側でも常時非表示。移動中だけ既存の発光・420〜479不可視規則と相手コート領域の解放（右190、左240、連続模様490）を適用する。縁70だけでは球を表示しない。単一の判定で本体・影・発光・輪郭を制御する。
- この残球速度と非表示の処理では、ランキング、共有、画面構成、増球・虹色・花火・スマッシュの進行は変更しない。共有と音響の変更は[統合計画](../plans/2026-10-24-share-speed-audio.md)に従う。Draft PRまで作成し、merge・公開は実行しない。

## 実装判断
生存数を毎フレーム速度へ直接反映すると飛行中の倍率固定を破る。基本倍率へ組み込むと最低時間で頭打ちになり、更新時に二重適用しやすいため独立値を採用する。予約済み待機球をそのまま加速すると到着間隔が壊れるため、打球確定時にもschedulerを通す。
