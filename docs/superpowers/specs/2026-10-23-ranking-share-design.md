# 任意参加ランキングとSNS共有

## 目的
ユーザーの依頼に従い、名前なしで遊べる卓球ゲームへカメレオンの実験場の共通ランキングを追加し、結果の共有と再プレイをしやすくする。PR #14は既にマージ済みのため、mainから追加PRを作る。

## 仕様と実装判断
- 名前は任意。空欄は通信不要のゲストプレイ。名前ありは前後空白を除いた1〜20文字（Unicode code point）を公開する旨を開始前に表示する。
- `start_game_play_v1`の受付成功時に開始し、開始の再送には同じ`start_id`を使う。プレイ数は開始時に1回。通常終了および明示的な途中終了は、その時点のラリー数を送る。ページ離脱はサーバーの仮リタイアを維持する。
- `finish_game_play_v1`→`submit_score_idempotent_v1`で自動送信。同一結果は同一`submission_id`。未送信結果は保存し、再読込後も再送可能。未送信結果を消さず、複数件を保持することで通信失敗中も再プレイできる。
- `game_id`と`game_slug`は新規に`takkeu`と定義。正式URLは既存の`https://chameleonjp-lab.github.io/takkeu/`。`shared`方式、整数ラリー数、降順、倍率1、小数0。
- スコア直下に「もう一度」。新しいプレイでゲーム・入力・音声・描画の前回状態を初期化し、ランキング表示はキャッシュを使わず再取得する。保存された自己ベスト・設定・名前・送信待ち記録は維持する。
- Xシェアはラリー数・タイトル・正式URLを含む投稿画面を開く。結果下部にベストスコア上位30名、RPCの同率順位、名前、ラリー数、プレイ回数を表示する。空・取得失敗・再読込も扱う。
- 実際のゲーム画面を参照した1200×630のSNSサムネイルを公開し、HTMLにOGP/Twitterカードの絶対URLを設定する。
- 既存のmain pushによるGitHub Pages公開を維持し、分割ブラウザ検証を使って公開処理の時間切れを防ぐ。検証後に追加PRをマージし、公開SHAと正式URLを確認する。

## 選択肢
既存の共通RPCを利用する。独自テーブル・認証・Edge Functionは既存の実験場集計を分断するため追加しない。ローカルだけのランキングでは依頼を満たせない。

## 制約・検証範囲
公開用Publishable keyのみ使用し、既存のRLS・共通RPCを変更しない。ゲーム物理と画面全体での直接操作を維持する。名前任意はユーザー指定として共通規約の名前必須より優先する。自動ブラウザと公開APIによる確認を記録し、実機iPhone Safariでの確認とSNS側の再クロールは未確認として区別する。

共通JSON Schemaはファイトフライト以外に名前必須を課すため、そのままでは今回のマニフェストを受理しない。依頼の名前任意を正とし、タッケウ専用の`docs/schemas/takkeu-ranking.schema.json`で契約を検査する。共通Schemaを別リポジトリへ変更する操作は自動承認審査に拒否されたため実施しない。この制約は既存の共通RPCの動作には影響しない。
