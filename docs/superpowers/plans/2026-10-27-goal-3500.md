# Goal 3500 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 3000を通過点、3500を唯一の最終ゴールにし、短い節目演出と互換性を維持する。
**Architecture:** 既存simulationの終端境界、共有feedback batch、独立表示時計、版別RPCを使う。
**Tech Stack:** TypeScript, Three.js, Vitest, Playwright, PostgreSQL/PGlite.
**Spec:** docs/superpowers/specs/2026-10-27-goal-3500-design.md

## Global Constraints
- 物理・最大30球・難易度・入力・遅延停止を変更しない。
- 旧スコアと旧pendingを保持。共有score_maxを3500にしない。
- 本番DBの新migration適用、main push、merge、公開は禁止。
- Stage A/B/Cの3段階commit。Draft #27を更新。

## Review Focus
- 同時hitと100球lossの時刻/同時刻ball-id順。
- 非表示/復旧/retry後の古い演出再開と通信所有権。
- 新ルールで旧RPC経由のscore範囲迂回。
- 旧3000 pendingが新3500 RPCへ送られないこと。
- 1500以上でeffect期限後のvertex/uploadが0であること。
