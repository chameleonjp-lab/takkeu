# 増球タイミングと公開画面の照合計画

> **For agentic workers:** Use superpowers:executing-plans. 既存の隔離worktreeで順に実装し、最後に別コンテキストのレビューを行う。

**Goal:** 公開版の未反映原因を特定し、最新指定の5・10・以後10ラリーごとの増球を、既存の暗闇・発光・接触へ統合する。

**Architecture:** 計算とThree.js描画の分離を維持する。増球数と報酬到達点を定義する既存の2関数だけを変更し、演出の閾値・配球予約・速度・接触を変えない。

**Tech Stack:** TypeScript / Three.js / Vitest / Playwright Chromium・WebKit。

**Spec:** [正式要件書](../specs/2026-10-22-takkeu-design.md)と2026-10-23のユーザー指定。今回の増球指定を旧30/40/150より優先する。

## Global Constraints

- 開始1球。5で1球追加して計2球、10で2回目の追加を行い計3球、20で計4球、以後10ごとに1球追加。無落球なら21で4球、450で47球。上限・落球補充なし。
- 毎ラリー加速、M10の5秒、M30の常時発光、M05の増球行を含む全22行、390の各0.3秒の強弱、420の相手球不可視、450のスマッシュは維持。
- ワンバウンド後の投影接触、深度、固定画角、予約済みの時刻と速度を維持する。
- 自動マージは禁止。mainへマージ後の自動Pagesと手動expected_shaを維持。公開SHAを実際に照合し、実装済み・検証済み・公開済みを区別する。
- 実機・試聴・点滅安全性とLinux性能未達を、自動検査成功で上書きしない。

## Review Focus

- 4→6や9→11の複数同時接触でも、増球が各一度だけ発生する。
- M10の増球と5秒の発光、M30以降の増球と常時発光が競合しない。
- 落球後も累積報酬は再配布せず、待機球を含む全球消失だけで終了する。
- 450の47球以上で配球間隔・リトライ時の資源再利用・音の上限を維持する。
- main/公開のSHAが異なる場合に、公開済みと誤報告しない。
