# 最新ラリー要件の反映計画

> **For agentic workers:** Use superpowers:executing-plans. 既存のworktreeで本担当が順に実装する。追加エージェントは使用しない。

**Goal:** ユーザーが再提示したラリー一覧を現在のThree.jsゲームへ反映し、旧要件の検証記録と新しい結果を区別する。

**Architecture:** 固定刻みの計算と描画の分離、ワンバウンド後の投影接触、低い固定画角、深度判定を維持する。既存の進行処理を毎ラリー加速・繰り返し増球へ変更し、床・壁を独立部品として解放する。球の描画資源は共有し、表示中の球へ再利用する。

**Tech Stack:** TypeScript / Three.js / Vitest / Playwright Chromium・WebKit。

**Spec:** ユーザーの最新一覧、および更新する `../specs/2026-10-22-takkeu-design.md`。今回の数値が従来のM05/M50/4球上限/初期の相手表示より優先する。

## 制約と確認事項

- 開始1球、30で2球、40で3球、150で4球、以降10ごとに1球。補充ではなく累積報酬で、落球しても再配布しない。450で無落球なら34球。
- 加速は毎ラリー。旧来の5の倍数での倍率と上限2.2は保ち、その間も連続的に増加させる（指数の分母200）。予約済み時刻と倍率は維持。
- 相手側は発光した部位だけを表示する。380は相手側の床、410は自側の床、420は相手側の壁と相手側の球の再不可視。
- 390は解放済みの非球部品だけを各0.3秒で滑らかに強弱させる。未解放の床・壁を先取りしない。球・HUD・予告を点滅させない。
- 270の「無地色」はユーザーへ確認中。それ以外は独立して実装する。返答がなければ今回の文字どおり単色（既存の赤）を採用し、390から虹色にする。
- 公開の自動反映・expected_sha・ロールバックは既存構成を保つ。Draft PRを更新し、自動マージしない。

## Review Focus

- 160等で増球と部位解放が同時に起きても両方が一度ずつ成立する。
- 4球以上・失球後でも報酬数と単調増加IDが正しく、同じ得点で補充しない。

- 非表示・リトライ・390・420で球の白中心、虹色、影、古いモデルを漏らさない。
