# 30球上限と同時返球 Implementation Plan

**Goal:** 残球全体を最大30球、増球を最大3ラリーに1球とし、全球の返球を直列化していた待機列を解消する。
**Spec:** この会話の追加依頼（MAXストックと同時返球数30球、毎ラリー追加と複数球追加を廃止）。
**Architecture:** 累積報酬と実際の残球上限を分け、満杯で消費した報酬を持ち越さない。各球は自分が相手へ到達した時刻に基づいて返球し、他の球の到着予約で延期しない。
**Tech Stack:** TypeScript, Three.js, Vitest, Playwright.

## Global Constraints

- 初期1球、5/10/20/30/40の増球、50から4ラリーに1球、140以降は141から3ラリーに1球。以降は3ラリーに1球を継続。
- 待機・往路・復路を合わせて30球まで。満杯時の追加は見送り、次回の増球時に空きがあれば1球追加する。
- 30球が同時に返球可能なときは30球が飛行に参加できる。スマッシュの0.4秒予告、飛行時間、単球速度、当たり判定は維持。
- 返球元は3帯の交互巡回を廃止し、連続した位置へ散らす。同じ側からの連続返球も許容する。
- 虹色コートの表示、300以降の増速、結果シェア・ランキング導線は維持。

## Tasks

- [x] 累積報酬と30球上限のAPIを分け、既存進行テストを新しい頻度へ更新する（担当エージェント）。
- [x] 30球の実返球・満杯時の報酬消費・空き発生後の追加・返球位置の回帰テストを先に失敗させる。
- [x] 同時返球を妨げる全球間の待機を廃止し、実球生成時に30球上限を適用する。
- [x] 旧仕様の直列到着・数百球を前提とした検査を、30球の同時飛行・継続・落球・上限検査へ改める。
- [ ] 型・単体・両ブラウザ・配布を検証し、独立レビュー後にPR #22へ追加する。

## Rulings

- 最大30球は待機球と飛行球の合計と解釈する。別々に30球ずつを保持すると残球が60になり、依頼の150球ストック問題を残すため。
- 到着順に全て拾えることを保証する旧間隔より、30球まで同時に返る要求を優先する。球を失えば残球を減らす実際の判定を維持する。

- レビュー指摘により、138→140の2ラリー間隔も廃止する。最新の最短3ラリー指定を優先し、138の次は141、144…にする（無落球時の30球到達は141）。

## 検証の進捗

- 修正前に30球中1球しか返らないことと、満杯で31球へ増えることを回帰検査で確認。修正後は当該9件すべて成功。
- 型検査、単体47ファイル618件に成功。30球からの30秒の継続、失球・増球の厳密な球数、30/60/120Hzの入力再現を検証。
- 独立レビューで指摘された138→140の2ラリー間隔を141へ修正し、最初の5000報酬の間隔を検査。再レビューで解決済み。
- 実装コミット作成時点でChromium全67件が成功。WebKit67件と配布検査を継続中。最終の検証結果はPR #22の説明・チェック欄を参照する。
