# Goal 3000 and Hall of Fame Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; use a fresh independent reviewer for the completed change. Steps use checkbox syntax for tracking.

**Goal:** 3000ラリーでクリアし、新ルールの初回クリアに登録名単位の殿堂番号と賞状を提供する。

**Architecture:** 既存の終端phaseに明示的な終了理由を追加する。専用RPCが新ルールのセッションと検証済みスコアを結び付け、クライアントは永続再送を通して番号を取得する。賞状は結果画面でのみ生成する。

**Tech Stack:** TypeScript / Three.js / DOM / Canvas 2D / Supabase PostgreSQL / Vitest / PGlite / Playwright.

**Spec:** `docs/superpowers/specs/2026-10-27-goal-3000-design.md`

## Global Constraints

- 3000到達前の最大30球、難易度、入力、当たり判定、fixedDt、maxSteps、slowFrameSecondsを維持する。
- 番号は登録名ごとの初回登録順。同名再クリアは同じ番号。旧記録は番号付与・削除しない。
- 正式番号はサーバー検証後。新旧の保存済み再送と既存ランキングを保護する。
- 本番へのテスト送信・DB反映・マージ・公開を行わずDraft PRへ提出する。

## Review Focus

- 同一tick内の30球返球で3000を超えたり、終了後に失点しない。
- スコア送信後に通信が切れても番号が重複せず、次回起動で再送する。
- 同名・別名の並行登録とランキング対象外への変更で番号や公開範囲が壊れない。
- 旧版の保存済み結果を新ルールのクリア扱いにしない。
- 結果を離れた後の応答・PNG生成で別プレイの番号や画像を表示しない。
