# 準備済みプレイの即時開始 Implementation Plan

**Goal:** 「今の実装意図は残しつつ読み込み不要な場合はすぐにゲーム始められるように」という追加依頼を実装する。
**Architecture:** 初回・描画復旧後は既存の事前準備と案内を維持する。準備済みの描画を使う場合は画面描画待ちを省き、現在の操作座標を同期確認する。音声・ランキング・座標で実際に待つ場合だけ150ms経過後に案内を表示する。150msは表示の条件であり、開始の最低待ち時間にはしない。
**Tech Stack:** TypeScript / Three.js / Web Audio / Vitest / Playwright。
**Spec:** 上記ユーザー依頼と、既存の `2026-10-25-startup-loading.md` の準備・キャンセル・資源再利用の契約。

## Decisions

- 単に案内を隠す方法では必須のフレーム待ちが残る。準備を全て省く方法では入力やランキングの準備を飛ばすため、既存の準備済み判定を使って待ち方を分ける。
- 初回の重い描画準備前は案内を先に描画する。再プレイ時の有効な表示寸法と操作座標はその場で確認できるため、複数フレームの安定待ちは不要。
- 読み込み中の進行・入力停止、残り時間の目安、中央のルール・終了条件、失敗・キャンセル・描画喪失・遅い応答の処理を保つ。
- 既存PR #24のブランチで追加修正する。新しい依存関係や事前のバックグラウンド準備は追加しない。

## Review focus

- ポーズ・結果・ホームからの準備済み開始は、追加のRAFを要求せず案内を一度も表示しない。
- 速い名前ありランキング応答も案内表示の150msを待たず開始する。
- 音声やランキングが遅い場合は待機中の進行と入力を止め、案内を表示する。
- 現在のコート寸法が0または座標が無効な場合は、古い有効座標が残っていても開始しない。
- 案内が出る前の中断や、出た後のキャンセルでも、古い応答から開始しない。
