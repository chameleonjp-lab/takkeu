# Rally 4000 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or executing-plans. Track work here and in docs/verification/rally-4000/progress.md.

**Goal:** Add every requested in-game rally/loss/best visual and audio cue through 4000, preserving playable physics and PR26.
**Architecture:** A pure presentation controller consumes confirmed events independently of progression rewards. A bounded renderer draws its state with fixed GPU resources; app supplies the run-start best and extends only the finish drawing clock. Audio/UI remain independent consumers.
**Tech Stack:** Existing TypeScript, Three.js, Web Audio, Vitest, Playwright Chromium/WebKit.
**Spec:** ../specs/2026-10-25-rally-4000-design.md and user's full 17-chapter request.

## Global Constraints
- No physics, camera, collision, control mapping, score calculation, balls/rewards, ranking API/schema or production data changes.
- Preserve resultComments/resultEffects/result.css/resultPosition and result layout, 44 comments, 2000+ fixed comment.
- No production test score setters/URL parameters. All browser harnesses stay tests/.
- simTime controls in-game effects, reset per run, dedup confirmed events, bounded history; no gameplay RNG consumption.
- 1000/3000/4000 replace normal fanfare; 2000 keeps existing. Warning remains audible at voice cap.
- Finish score/communication immediate; drawing only, maximum 5 seconds. 4001+ continues.
- Separate implementation, automated checks, observed images/motion, waveform analysis, human listening and device testing verdicts.
- Draft PR only; no merge, deploy, auto-merge or production score submission.

## Review Focus
1. Multiple scores/losses in one fixed-step frame: retain each event and its real position.
2. Pause/resize/context restoration: no arrival replay or elapsed time jump.
3. 100th loss: physics stops while final visual survives, ranking immediate.
4. Warning during dedicated fanfare at voice saturation: audible and bounded resources.
5. 2000+ background visibility through actual camera and opaque rainbow court, mobile input/HUD readability.
