# 起動準備とラケット入力の安定化 Implementation Plan

**Goal:** 必要な準備が済んでからプレイを開始し、進捗・所要時間の目安・中央寄せのルールを表示する。再プレイでは描画資源を再利用する。
**Architecture:** ゲーム本体のphaseにロード状態を混ぜず、アプリ側で準備とキャンセルを管理する。描画・音声の準備完了と操作座標の確認を開始条件にする。
**Tech Stack:** TypeScript / Three.js / Web Audio / Vitest / Playwright。
**Spec:** ユーザーの開始時ローディング・進捗/時間表示・再プレイ再利用・中央寄せの説明の依頼。

## Findings and decisions

- PR #23 はマージ済み。main `b531d66` から `codex/startup-loading` を作成。
- 初期素材はDataTextureと合成音として内蔵されている。ゲーム中に追加アセットを取得する仕組みはない。
- ウィンドウのresizeを伴わずコートの高さが2px変わると、古い操作座標が無効になって入力が捨てられる。Chromiumで「期待x=.6、実際x=0」を再現。
- 初回は通常/発光の描画プログラムとテクスチャ、音声の共通データを準備する。音声拒否は案内して無音で開始できる。
- 進捗は完了した実作業から計算し、残り秒は目安と明記する。長引く場合は経過時間へ切り替える。待たせるための固定時間は設けない。
- 再プレイではrenderer・geometry・texture・音声Context/cacheを再利用する。球・入力・得点・落球・演出・runIdは新規に初期化する。
- 読み込み中のキャンセル・失敗・画面離脱・描画喪失から勝手に開始しない。準備失敗では再試行/ホームを表示する。

## Interfaces

- `LoadingState`: `{percent:number;stage:string;remainingSeconds:number|null;elapsedSeconds:number;error:string|null}`。
- `createLoadingScreen(root, {cancel,retry})`: `{show(state:LoadingState|null),dispose()}`。独立した画面とCSS。
- `GameView.prepare?(onProgress:(completed:number,total:number)=>void):Promise<void>`。初回の準備を共有し、復旧時は新しいviewで再実行。
- `GameAudio.prepare?():Promise<boolean>`。無音で共通データを用意し、後続の打球で再利用する。
- アプリは読み込み中のゲーム進行/入力を止め、コートの表示サイズ・座標を再確認してから開始する。

## Review and verification notes

- 読み込み中のゲーム時間・入力停止、再プレイの描画再利用、失敗後の手動再試行、キャンセル後の古い完了通知、描画復旧、280px/200%の案内表示はChromium/WebKitで確認。
