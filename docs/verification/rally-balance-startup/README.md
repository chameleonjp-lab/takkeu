## ポーズの原因と修正

従来のライフサイクル処理は、`resize` / `orientationchange` が通知されるだけで無条件に停止していた。サイズ不変の通知やモバイルの名前入力キーボード・ブラウザツールバーの高さ変更を、開始直後に発生させて再現した。

修正後は実際の幅・高さ・画素比・回転角を比較する。サイズ不変通知では停止せず、モバイルの高さのみの変化では描画と入力マッピングを更新する。実際の回転・幅変更・デスクトップのサイズ変更・非表示・描画喪失等では引き続き停止し、明示的な再開を待つ。

独立レビューで、高さ更新によってドラッグ中の所有ポインターが消える点を検出した。再現テストを先に失敗させ、プレイ継続中の再配置では同じ指の追跡を保持するよう修正した。途中の二本指タップ候補は破棄し、回転・中断時は以前どおり入力を消去する。

774球からの継続検査は`extended-load.spec.ts`へ分離した。ソフトウェアWebGLでは動画・DOM/画面トレースの読み戻しが大きな負荷となるため、この1件だけ連続記録を無効にした。450・555からの多球継続は10Hz相当の描画で本番の追いつき処理を通し、120Hzの物理計算を進める。シミュレーション時刻も29.9〜30.1秒に達することを検査する。30ゲーム秒、解像度、増球・スマッシュ・粒子数・描画回数の判定は維持し、最終画像と状態JSONを保存する。機能検査の実行予算と、実時間の性能測定は別に扱う。

この環境にはWebKitの共有ライブラリが不足していたため、Debianの署名済みパッケージを`/tmp`に展開してブラウザへ接続した。ブラウザ本体はPlaywrightの固定バージョンを使用し、システム全体のライブラリは変更していない。ホストライブラリ検出をスキップする環境変数は、このローカル配置を自動検出できない検査にのみ使用した。
