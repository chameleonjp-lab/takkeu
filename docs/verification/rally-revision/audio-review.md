# 音声処理と試聴の記録

対象製品 `eb02cb0c63f122a2410ddc4c8e0cbb9955f34d5d`。音声コード自体は先行の貫通修正から同一で、今回の増球に合わせて検査を拡張した。

| 確認 | 結果 | 条件 |
|---|---|---|
| 実AudioContextの開始・自他ノード・ミュート・中断と復帰 | 成功 | Linux Chromium／WebKitの自動操作。再開拒否・生成失敗でもゲームを進め、次の操作で復旧。 |
| 自他・予告・4重・16重の実合成 | 成功 | OfflineAudioContext、mono 44.1kHz。各WAVと波形値を保存。 |
| 34イベントを各一度、同じイベントの再投入は破棄 | 成功 | 単体の計測用AudioContext。全34音を個別生成し、同時接続は8音＋最大8本の短いフェード尾以下。終了/旧runの音は破棄。 |
| 音割れの数値検査 | 成功 | 16重合成の最大絶対ピークはChromium0.5928182、WebKit0.5928183。8音＋8尾の最大数に対する検査であり、34音を上限なしに同時再生したものではない。 |
| 人による返球音の聞き分け、予告との音量バランス、不快感 | 未確認 | 本環境で試聴できていない。波形・数値を聞いた合格へ読み替えない。 |
| 実iPhone 17 Pro Safariでの音声開始制限・画面ロック後復帰 | 未確認 | 実機なし。WebKitの自動検査だけでは合格にしない。 |

`audio/{chromium,webkit}-{player,opponent,warning,four,sixteen}.wav` の10本と、`data/*-waveform-measurements.json`、正式単体/画面ログを参照。残る確認は、実機のスピーカー/イヤホンで自他の返球と予告を聞き分け、390以降の映像と多球時にも不快な重なりがないことを確認すること。
