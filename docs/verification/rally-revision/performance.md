# 性能・寿命と計測条件

対象製品 `eb02cb0c63f122a2410ddc4c8e0cbb9955f34d5d`。速度・判定・視認時間・配球間隔・停止閾値を、描画負荷の軽減のために変えていない。最新指定による毎ラリー加速・繰り返し増球は別の明示された改訂。

## 成功：固定時計の多球・寿命検査

Chromium／WebKitとも、450の無落球34球から約30ゲーム秒（29.9917秒）を継続し、579ラリー・46球でrunningを維持。初期34球が全て相手から打たれ、スマッシュも実行されたことを検査。4球の回帰、最大速度付近の接触、34球以上の30/60/120Hz一致も成功した。

両エンジンでgeometry45・texture4・program11が一定、描画呼出し48〜69。球の形状と基本材質を共有し、可視球へモデルを割り当てて再利用。発射待ちや落球へ描画資源を固定しない。球数上限で負荷を隠していない。

再挑戦20回＋ホーム20回は両エンジンとも同じ基準状態を維持。listeners22、rAF1、AudioContext1、geometry42・texture4・program9。完全破棄後はlistener0・rAF0、音声ノードも停止/切断。AudioContextの生成累計1を、稼働ノードが残る意味に読み替えない。モデルのID再割当20回と共有geometryの一度だけのdisposeも単体で確認。

## 再確認：描画準備後も遅延停止

開始直後の準備だけが原因かを切り分けるため、同じソース・設定で `warm-load.mjs` を追加実行。390で3ゲーム秒まで準備し、その間だけ必要に応じて再開した。450へ切り替えて手動で再開してからは、一切再開せず、中断した時点で測定を終了する。ソースの全105ハッシュが正式対象と同一であることを照合した。

- Chromium：準備中に遅延停止1回。計測309.5ms、実進行0.2000秒で再びslow-frame停止。
- WebKit：準備中に遅延停止3回。計測580ms、実進行0.3167秒で再びslow-frame停止。
- pageerrorは両方0。停止閾値0.10秒、品質、球速、計算を変更していない。計測中の自動復帰で連続プレイに見せかけていない。

再確認も失敗で、冷えた開始だけでは説明できない。全間隔・初期/最終状態・準備中の停止・条件は `data/warm-{chromium,webkit}.json`、実行記録は`warm-load.log`へ保存。詳細な遅延の内訳と実機再現性は未解決。
