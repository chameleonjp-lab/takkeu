対象ソース：`1e13fd4281721a2b843967a3b69b5801088da26e`。LinuxのChromium 156／WebKit 27.2、条件はenvironment.json。iPhoneの実撮影ではない。

## 開いて確認したもの

- 画像38枚を[PC比較一覧](review/screens-chromium.png)と[WebKit比較一覧](review/screens-webkit.png)で確認した。
- 設定、ホームの200%文字、縦ゲーム、横ゲーム、実WebGL復旧後の予告を原寸でも開いた。メニューは読み取れ、ボタンと安全余白が保たれる。200%のスマホ縦は折返しとスクロールが必要になる。停止ダイアログ内の操作はスクロール・フォーカス移動でも到達できることを画面検査で確認した。
- 390/450の実WebMをffmpegで読み込み、末尾2.2秒／3秒から10fpsの連続フレームを抽出し、各20枚の一覧を開いた。[390 PC](review/pulse-chromium-frames.png)／[390縦](review/pulse-webkit-frames.png)／[450 PC](review/smash-chromium-frames.png)／[450縦](review/smash-webkit-frames.png)。元動画はmedia/に保存した。

## 390の観察と安全性の範囲

描画された強弱と色の変化は連続しており、形が消える暗転は見られない。球の明るい中心とHUDは追える。台・身体と球を別々に認識できる。450でも文字予告は背景の強弱から独立し、隠れた球は相手側に描かれず、自側へ出ると見える。

周期0.6秒、各遷移0.3秒、球・背景・HUD・予告を対象にしないことは単体でも検証した。動画には音声を収録していない。

**最終的な点滅基準は未確認。** 通常速度の動画を人が再生して試遊した記録ではなく、実動画からの連続フレーム確認である。10fpsの抽出は短い閃光をすべて否定する方法ではない。実iPhoneでの明るさ・面積・赤色の変化、最大速度での移動・4球を含む全体をWCAG 2.3.1に照らして公開前に確認する。周期の数値やこの一覧だけを安全性の合格として扱わない。不適合なら演出を修正し、該当する映像と検査を更新する。
