# 適用前提と公開手順

このPRはソースと新規SQLを準備した状態。本番への適用・マージ・Pages公開は行っていない。ユーザーの公開許可後に運用者が実施する。

## DB

前提はmain `628439f` の既存ランキング保護・進捗・最終落球数が導入された共有DB。既存7本のSQLは本番で適用済みのため、今回まとめて再適用しない。新規は [20261027032043_takkeu_hall_of_fame.sql](../../../supabase/migrations/20261027032043_takkeu_hall_of_fame.sql) の1本。

適用前にprivate.game_play_sessions、public.score_runs/players/game_scores、normalize_player_name、start_game_play_v1、finish_takkeu_play_v2、submit_score_idempotent_v1を照合する。今回のread-only確認ではranking_statusはNOT NULL、名前正規化はtrimのみだった。新ルールだけ3000上限にし、共有games.score_maxや旧記録の値を変更しない。

新規SQLを単一トランザクションで適用する。新テーブルはRLS有効・anon/authenticatedの直接読み書きを許可せず、公開RPCに必要なEXECUTEのみ付与する。新開始RPCで始まったcurrent-versionプレイだけを対象にし、旧開始IDを新ルールへ格上げしない。旧データへのINSERT/UPDATEによる殿堂移行は存在しない。

適用後は参照だけで関数・列・RLS・GRANT・殿堂が空であることを確認する。本番へテストのクリア/スコアを送信しない。実際のプレイヤーの新ルールでのクリアから番号を付ける。

## フロントエンド

DBを先に準備してから、承認されたmainのコミットを既存のPages公開フローで配布する。新clientVersionはtakkeu-web-clear-1。新RPCがない場合、名前ありの開始はエラーとして再試行を案内し、偽の番号を発行しない。名前なしのゲームと番号なし賞状は利用できる。

旧clientVersionの保留記録は元の終了/送信API、元のスコア範囲で処理する。匿名開始の版も維持する。新しい名前あり開始の保存キーだけv2に分けている。過去3000超のランキングと自己ベストはそのまま表示し、新ルールが3000ゴールである説明を添える。

番号はDB登録確定順。オフライン中の端末時刻を信じて先の番号を予約しない。本人認証や人間の操作の暗号学的証明を新設するものではなく、既存の登録名・セッション・サーバー時間整合の制約を引き継ぐ。同名の別人は区別できない。

殿堂の表示対象外化では行・番号を削除/再採番せず、現在のranking_statusで公開を除外する。既に保存・共有されたPNGを後から回収できる保証はない。既存データや新しい未送信結果があるため、ロールバック時も新しいDB資源を機械的にDROPしない。
