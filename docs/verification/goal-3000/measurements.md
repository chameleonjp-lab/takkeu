# 性能・メモリ・画面と安全性

## 今回の測定範囲

新ルールの終了後に描画を続けないことと、結果/賞状/再挑戦での資源保持を測定した。60Hz仮想時計によるフレーム記録は実機FPS測定ではない。今回、3000未満の新たなnative p50/p95/p99や実時間60秒の性能比較は実施していない。

0からの実物理リプレイは3000点、25684固定tick、ゲーム内214.033333秒、落球0、最大30球でclear。各返球の加点は1、clearイベントは一度。ゲーム終了後は時刻も得点も進まない。これは計算の検証であり、214秒の実時間操作試験を意味しない。

クリア後の各6秒・360フレームで、得点3000・30球・snapshotは固定、追加の3D render呼出しは0。renderer.infoのdrawCalls=28は最後の描画値が残った値であり、終了後の毎フレーム28命令を意味しない。GPU資源は再挑戦に再利用する。

## 賞状と反復資源

402×874 CSS、DPR2、標準描画603×1311のLinux Chromium/WebKit。両方で5回warmup後に20回のクリア→900×1200 PNG生成→ホーム→再開始を測定した。canvasは1個、古いPNGのsrc参照はnull、geometry55・texture4・program17・buffer容量は同じ経路内で一定。以前の別のwarmup手順のgeometry32と直接比較しない。

仮想performance.memoryは利用できずnullだったため、Chromiumでは別にCDPの実GCとRuntime.getHeapUsageを用いた20回測定を追加した。JS使用量12,281,008→12,707,424 bytes（+426,416）、backing storage 10,128,331→10,128,331 bytes。原因を分離しておらず、増加ゼロ/無期限の無漏洩を主張しない。WebKitの同等heap値、ネイティブ画像キャッシュ/GPU総byteは取得できない。

## 見た目・入力・音

クリアは静的な金色数字・見出しと殿堂/賞状のカード。clear時は結果SVG電撃を起動せず、CSSアニメーションを抑止する。生成中/共有中に結果を離れた場合はepochと所有fileを照合し、古い画像やエラーを新しい結果へ持ち越さない。画像URLは離脱/再生成でrevokeする。

3000未満のボール、ラケット、カメラ、入力マッピングはソースを保護した。既存の独立投影による1 CSS px未満のタップ/ドラッグ受入基準を保ち、両エンジンのCIで回帰検査する。到達前の30同時返球も継続し、2999からの最後の有効打球で3000に達した場合だけ終端とする。

3000到達音はgame-clearイベントで通常音を終了し、ファンファーレを自然終了させる。画面を静止させるために同じRAFでsuspendしないことをapp/domain双方で検査した。実際のiPhoneの音量/聞こえ方、OSのファイル共有/写真保存は未確認。

## 点滅

元の解析スクリプトSHA256 `daf77a431d9585044b30b64fa6d2f2e2a452f6c0ca621e2c4466dd64d2551f5d` と閾値を維持し、自己試験5件が成功。新しい静的clear画面の360フレーム×2で、一般/赤色のflash closingと頻度超過は0、flagged=false。全画面・元比率を使い、領域マスクや引伸ばしを行っていない。

追加の画素完全一致試験はChromiumで未達（最大1/255のチャンネル差、最大10画素、細い枠線）、WebKitでは一致した。最初の一致試験の失敗も保存し、基準を1へ緩めて成功扱いにはしていない。画素差の有無と元の点滅判定を分けて報告している。

これは終了画面のSDR自動スクリーニング。以前の7警告や旧実物理4000の警告を「解消済み」と扱わない。4000は新ルールでは到達しないが、3000以前の既存警告・人間の視認・正式WCAG/HDR・iPhone実機は未確認/未解決として残す。prefers-reduced-motionも維持した。
