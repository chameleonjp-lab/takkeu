# 返球の左右分散・発光タイミングの照合

検証日：2026-10-23 UTC。基準main / 公開版は `547cec0654c18c8739752ae1ef322dde42086ee7`。実装・テストの確定コミットは `20f175116f7816d0818d6b432a4b442690a44d3d`。初回検証は `0b330d49516b92d3278d614e6262846374b09a25`、追加の555修正後に影響する検査を再実行した。この記録を含む後続コミットは文書・証拠の追加のみ。

**配球は修正済み。発光タイミングの報告は未再現で、修正済みとは扱わない。今回の配球修正は未公開。** 実公開のHTML資産・SHAは [public-before.json](public-before.json)。

## 原因と修正

以前は自側の終点を左右3帯に分ける一方、相手の打球地点を独立に乱数化していた。ワンバウンド直後の球を遠近投影すると、終点が左でも中央のラケットに当たっていた。既存の「最小・最大の終点が広い」という検査では実接触の偏りを検出できなかった。

往路の打球地点と次の返球先を同じ左右帯へ配置した。候補は左・右各約40%、中央約20%、帯内の位置・高さは乱数で変わる。追加球も同じ方式。初回サーブは中央。

固定seed 7・3,000組の往復計画を作り、バウンドから到着後0.35秒まで実際の投影接触関数で検査した。ラケットは `(0, 0.5)` に固定。

| 観測 | 修正前 | 修正後 |
|---|---:|---:|
| 中央固定で返せる球 | 1,655 / 3,000（55.2%） | 550 / 3,000（18.3%） |
| 左の終点 | — | 1,222（40.7%） |
| 右の終点 | — | 1,193（39.8%） |
| 中央の終点 | — | 585（19.5%） |
| 左右を狙った球が中央固定で当たる数 | — | 0 |

[失敗を再現したテスト](return-spread-red.log)・[修正後の回帰検査](return-spread-green.log)・[全3,000組の位置データ](return-spread-data.json)・[分布グラフ](return-spread.png)。この統計は実機プレイの勝率ではない。

555以後には別の偏りが残っていた。左の終点へ近づいた後、バウンド点をさらに中央へ寄せていたため、左右配球の修正後でも左の球1,222本が中央固定に当たった。バウンド点を対象レーン側で始点・終点の外へ置くよう修正し、方向反転と台内の落下を保った。[1,000本による失敗の再現](late-bounce-red.log)と[最終3,000本の実シミュレーション](late-bounce-final.json)を保存。

| 最終の実シミュレーション | 中央固定で接触 | 左右を狙った球の中央固定接触 |
|---|---:|---:|
| 通常 | 550 / 3,000（18.3%） | 0 |
| 450・スマッシュ | 550 / 3,000（18.3%） | 0 |
| 555・方向を変えるバウンド | 536 / 3,000（17.9%） | 0 |

球速の設定、加速式、飛行時間の更新、接触、時間予約、遅延停止と描画の19ファイルは基準と同一。[SHA-256照合](preserved-behaviour.json)。軌道補間の`bounceTime`・`sampleReturn`も基準と同一。横方向の移動先と555以後の反転点を変更し、飛行時間と速度調整値を保った。

環境：Linux、Node 24.19.0、npm 11.9.0、Playwright 1.64.1。Chromium 156（SwiftShader）とLinux WebKit 27.2（iPhone 13の画面・タッチ設定）。実機iPhone Safariとは区別する。

画面検査は重複しない2組に分割する。先行14件の実行時には未コミットだったが、製品・画面テスト・補助コードは初回コミット`0b330d4`と同一で、その確定までに変更したのは単体の操作時系列2件だけ。追加の555反転と予告専用fixtureの変更は、先行14件が実行する経路では呼ばれない。残る62件は初回コミットで実行し、追加修正後に影響する555・ホーム粒子・スマッシュ予告の6件を再検査する。450の連続検査は両エンジンとも539で終了したため555の反転変更の影響を受けない。最終配布検査は追加修正後の確定コミット上で実行する。

最終の555検査は両エンジンとも30ゲーム秒で670ラリー・149球に到達し、全スマッシュ・増球・描画回数・粒子容量・ホームでの消去条件を通過した。450検査は539ラリー・83球。[各実行の高負荷結果](load-results-summary.json)。これは時計を制御した機能検査で、実時間の性能合格ではない。

[最終マニフェスト](manifest.json)に実装SHA、型・単体179・画面76・配布4の結果、ソース118ファイルと証拠190ファイルのSHA-256、未確認事項を保存した。

`dist/release.json` は確定コミットと `/takkeu/` に一致：[release-candidate.json](release-candidate.json)。[配布候補ZIP](pages-candidate.zip)・[配布10ファイルのSHA-256](distribution-sha256.json)。公開操作・自動マージは行っていない。ユーザーがPRをmainへマージした後、既存Pagesがそのmain SHAを照合し、同じチェックアウトの検査・ビルド成果物を自動配布する。[公開・確認・復旧手順](../../release.md)。

## 映像・音・失敗の記録

実ドラッグ動画の時系列フレームを開き、最初の中央返球から右・左へラケットを動かして3ラリーへ到達することを確認した。[Chromium](drag-contact-sheet-chromium.jpg)・[WebKit](drag-contact-sheet-webkit.jpg)。元動画と抽出フレームはこのフォルダ内に保存。Playwrightの時計で進めた機能検査であり、実時間の性能測定には使わない。

音声処理は両ブラウザの実Web Audioで確認。波形WAVも先行14件の証拠に含む。[音声・状態ファイル一覧](audio-and-state-index.json)（試聴用WAVを抽出済み）。**人による試聴は未確認**。実機iPhone 17 Pro Safari、390以後の最終点滅安全性も未確認。前回の[Linux実時間性能未達](../extended-rally/README.md)は解消したと扱わず、今回の範囲では再測定していない。

| 失敗・発見 | 原因と対応 | 再検証 |
|---|---|---|
| 中央固定で55.2%返せる | 終点だけの分散と、相手打球位置との独立選択。往復を同じ左右帯へ配置 | 18.3%、左右の球の中央固定接触は0 |
| 単体の2件が得点2を期待して失敗 | 中央に置いたまま2回返せる旧配球を前提としていた。4.7秒に左へ動かし、6秒に外す時系列へ変更 | 得点2、30/60/120Hzの全結果一致を維持して成功 |
| 公開SHA照合の子プロセスが終了1 | 制限付きシェルでのみ出力なしの失敗。ソース無変更で通常の検証実行条件へ揃えた | 単独と全単体で成功。最初の失敗を削除しない |
| 配布検査のブラウザ4件が起動前に失敗 | この環境のブラウザ保存先を指定し忘れた。`PLAYWRIGHT_BROWSERS_PATH=/tmp/takkeu-browsers`を設定 | ビルドを含めて再実行し4件成功 |
| 555の左配球が中央へ戻る | 旧反転点が中央方向へ寄る。対象レーン側で始点と終点より外に反転点を置く | 1,000本の回帰検査と3,000本の実計算で左右の中央接触0 |
| スマッシュ予告の画面検査2件 | 新しい中央配球は既存予約との余裕を守って発射が遅れ、テスト開始直後は予告前だった。予告検査の初期打球位置を、最初の空きに収まる右側へ固定 | 予告・ミュート・停止・再開・不可視を両ブラウザで再検査 |
| 555の高負荷検査が180秒制限を超過 | 30ゲーム秒の条件確認後のスクリーンショットに43.8秒かかった。機能検査の制限を240秒へ調整 | 実時間性能基準とゲーム条件は変更せず再検査 |
| 再検査のChromiumでページの実行環境が消失 | 開発サーバーへの再接続とページ再読込をtraceで確認。既存サーバーを終了 | 新規サーバーを起動する`CI=1`で該当検査を再実行 |

[最初の全単体ログ](unit-initial.log)・[最初の配布ログ](release-initial.log)を保存。音声復旧の旧テストはseed 7の中央固定で2回目の返球を期待していたため、修正後は余分な接触音が鳴らないことを確認する形に更新した。他の音声検査が自他の実発音を引き続き確認する。
