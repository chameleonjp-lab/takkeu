# 光の時間変化の検証方法

W3C WCAG2.1 Understanding2.3.1の本文を`wcag-three-flashes-source.txt`に保存した。出典: https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html 。引用部分は、一般閃光を「相対輝度0.1以上、暗い状態が0.8未満の対向変化の一対」、赤色閃光を「飽和赤R/(R+G+B)>=0.8を含み、CIE1976UCS距離>0.2の対向遷移」とする。1秒の回数に加え、1024×768の任意341×256領域の25%を面積閾値として調べる。

`tests/helpers/captureRallyFlashFrames.mjs`は、実際のcreateView/変更していないカメラ/不透明虹色コートを使い、1024×768CSS画面からsRGBキャンバスを60HzのsimTimeで6秒分取得する。実時間の性能試験とは独立しており、描画が遅くてもフレームを省略しない。1500/2000/3000/4000・標準/低画質の8組と4000・動きを減らす・両画質の2組を取得する。既存100単位・ゾロ目・連続落球99を新演出へ意図的に重ねるストレス用合成シーンで、物理的な進行試験とは区別する。

`tests/helpers/rallyFlashAnalysis.py`は各ピクセルのsRGBを線形化し相対輝度とXYZからUCSを計算する。微小な量子化揺れで極値を見失わないよう輝度0.1のヒステリシスで山・谷を抽出し、対向遷移を重複せず一対ずつ数える。赤色はUCSの2軸の極値と距離>0.2を調べ、軸の結果の和集合を保守的に扱う。サンプルの両端を含む61フレームが1秒に相当する。全ピクセルの1秒の回数と、閃光が閉じるフレームの面積を、積分画像により任意341×256窓で厳密に最大化する。空間的にずれた閃光の閉じるフレームを過大計数する可能性があり、検出時は該当時刻と領域を調べる。

4つの既知入力を使った自己検証（全面白黒6Hz、全面赤シアン6Hz、全面白黒2Hz、小面積白黒6Hz）を`--self-test`で行い、危険例を検出し、頻度または面積が閾値以下の例を区別する。正式ログは`../logs/flash-analyzer-tests.log`。

生フレームの全メタデータと解析結果を残す。PNGをFFV1へ圧縮する場合は`packRallyFlashEvidence.py`が全画像の元RGBバイト列と動画から復号したRGBバイト列のSHA256・長さの一致を確認してから、数値名の元PNGを削除する。元PNGごとのハッシュ・圧縮コマンド・動画のハッシュと確認結果を`lossless-verification.json`へ保存し、代表フレームも残す。

**判定の限界:** これは再現可能なSDRコンテンツのスクリーニングで、認定済みPEAT/Harding解析、HDR画面、実機の輝度・視距離、実機ブラウザの表示欠落を保証しない。キャンバス外のCSS通知は別途レイアウト・単発の登場回数を確認する。結果画面はこのゲーム中の解析に含まれない。回数・面積が検出上閾値以下でも、実機確認や人間の視聴覚確認を実施済みと記載しない。

## 圧縮と復元

大きな動画はFFV1での初回記録を経て、より小さい`libx264rgb -crf0 -preset medium`へ置き換える場合がある。どちらも全フレームをRGB24へ復号し、元フレームのRGBバイト列SHA256と長さが一致した場合だけ採用する。変更前後の動画ハッシュ・サイズ・コマンド・復号証拠は`lossless-verification.json`に保存し、旧FFV1の正式ログも残す。将来のフレームは直接RGBのlosslessH.264へ保存する。

GitHubのファイル上限を避けるため、動画/旧画像アーカイブは32MiBずつの`.part-000`等へ分割する。各`.parts.json`が元ファイルと各部分のSHA256を持つ。復元例（対象ディレクトリ内）:

```sh
cat capture-lossless.mp4.part-* > capture-lossless.mp4
sha256sum capture-lossless.mp4
ffmpeg -i capture-lossless.mp4 -pix_fmt rgb24 -start_number 0 %04d.png
```

復元動画のSHA256はpartsマニフェストと一致する必要がある。PNG再生成時の圧縮バイトは元PNGと異なり得るため、画素の一致は`lossless-verification.json`の連結RGB24ハッシュと復号長で確認する。元画像ごとのハッシュも省略せず残す。元フレームの解像度・数・時間・イベントを減らして圧縮することはしない。
